# ניתוב אוטומטי של כלי צ׳אט עם function calling ב־Gemini

זהו מסמך תכנון לשילוב «המשתמש כותב הודעה רגילה, המודל בוחר את הכלי הנכון» בכל צ׳אטבוט Gemini. הוא אינו
קשור למאגר קוד מסוים.

התבנית: **המודל שכבר עונה הוא גם זה שבורר את הכלי.** לא שמים מסווג זול מלפנים.

---

## 1. הבעיה

משתמשים לא יפתחו תפריט כלים. הם יכתבו:

> תייצר לי תמונה של קוף

> צייר תרשים זרימה של האימות שלנו

> מה זה endpoint אזורי?

שתי הראשונות דורשות מומחים (מודל תמונה, מציג דיאגרמות). השלישית היא צ׳אט רגיל. האפליקציה חייבת להחליט
**בכל תור**, לפי השיחה, לא לפי רשימת מילות מפתח.

קיצור מפתה: «קוראים ל־Gemini Lite, הוא מחזיר `image | graph | chat`, ואז קוראים למודל האמיתי.» זו בדרך
כלל ברירת מחדל שגויה. ראו §3.

---

## 2. מה לבנות במקום

שולחים ל־**מודל הצ׳אט הנוכחי** של המשתמש בקשת `generateContent` (או `streamGenerateContent`) שכוללת:

1. את השיחה
2. `tools.functionDeclarations` — הצהרה אחת לכל יכולת
3. `toolConfig.functionCallingConfig.mode = "AUTO"`

המודל עושה אז אחד משניים:

- משדר תשובת טקסט רגילה, או
- מחזיר `functionCall` (`name` + `args`) במקום תשובה סופית (או לפניה)

השרת שלכם מחפש את `name` ב־**רגיסטרי**, מריץ את הכלי, וממשיך את אותו סטרים כלפי המשתמש. הדפדפן עדיין
שלח בקשת HTTP אחת.

```text
שליחת משתמש
    │
    ├─ ממשק כפה כלי ──────────► מומחה בלבד (בלי מתכנן)
    │
    └─ Auto (ברירת מחדל)
            │
            ▼
     מודל צ׳אט + functionDeclarations AUTO
            │
            ├─ טקסט בלבד ──────────► משדרים את התשובה, done
            │
            └─ functionCall
                    │
                    ▼
             חיפוש ברגיסטרי
                    │
                    ├─ כלי handoff ─► קריאת מודל שנייה (תמונה, דיאגרמה, …)
                    └─ כלי loop ────► ביצוע, functionResponse, קריאה חוזרת למודל הצ׳אט
```

`AUTO` הוא המנגנון המקורי של Gemini: «אולי לקרוא לכלי, אולי פשוט לדבר.» אל תממשו אותו מחדש עם מסווג
enum, אלא אם יש בעיה מדידה של עלות.

## 3. למה לא נתב Lite

| | מסווג Lite קודם | Function calling על מודל הצ׳אט |
| --- | --- | --- |
| קפיצה נוספת | בכל הודעה, כולל «שלום» | רק כשבאמת נבחר כלי |
| המשכי עריכה | חלש («תעשה לו כובע») | רואה את אותה היסטוריה שהתשובה הייתה רואה |
| קבצים מצורפים | קל להשמיט או לטפל לא נכון | אותה בקשה רב־ערוצית כמו הצ׳אט |
| יצירת תמונה | עדיין צריך את מודל התמונה → **שלוש** קפיצות, או מדלגים על שכתוב הפרומפט | מתכנן + מומחה = **שתי** קפיצות, ורק בתורי תמונה |
| מי אומן לזה | אתם, דרך פרומפט | המודל, דרך `functionDeclarations` |

Lite-first הוא אופטימיזציה מאוחרת אם טוקני המתכנן הופכים לחשבון אמיתי, לא הארכיטקטורה שמתחילים ממנה.

## 4. שני סוגי כלים (לא לקודד `if` דו־כיווני)

שומרים רגיסטרי קטן. לכל רשומה יש `kind`. כלי שלישי אמור להיות אובייקט נוסף, לא ענף נוסף במטפל הסטרים.

### Handoff

מודל הצ׳אט הוא המנוע הלא נכון לעבודה. **עוברים** למומחה ומשדרים את התוצאה למשתמש. **לא** שולחים
`functionResponse` חזרה למתכנן.

דוגמאות:

- יצירת / עריכת תמונה → `gemini-3.1-flash-image` (או מודל התמונה שלכם) עם
  `responseModalities: ["TEXT", "IMAGE"]`
- דיאגרמות → אותו מודל צ׳אט, אבל הוראת מערכת נסתרת שמכריחה בלוק Mermaid מגודר, וה־UI תמיד מציג אותו

Handoff נכון כשהמשתמש צריך **לראות את פלט המומחה**, לא סיכום שלו.

### Loop

הכלי מחזיר **נתונים שמודל הצ׳אט חייב לקרוא** (תוצאות חיפוש, שורת מסד נתונים, מזג אוויר). מריצים את
הפונקציה, מוסיפים `functionResponse`, וקוראים שוב למודל הצ׳אט עד שהוא עונה בטקסט.

דוגמאות: חיפוש ברשת, שאילתת CRM, מחשבונים.

ל־Gemini יש גם כלים **מובנים** (`googleSearch` וכו׳). אלה אינם `functionDeclarations`; זו רשומת `tools[]`
אחרת. אפשר לערבב אותם אחר כך; אל תבלבלו אותם עם רגיסטרי ה־handoff.

גרסת v1 של המדריך היא handoff. מתכננים את הרגיסטרי כך שכלי loop יוכלו להתווסף בלי לשכתב את המתכנן.

## 5. כפייה מול Auto

נותנים למשתמש בוחר: **כלום / כלי א׳ / כלי ב׳** (XOR).

| הבוחר | התנהגות השרת |
| --- | --- |
| כלום (Auto) | מצרפים הצהרות, `mode: "AUTO"` |
| נבחר כלי | **לא** מצרפים הצהרות. קוראים מיד לאותו מומחה |

מצב כפוי מהיר וצפוי יותר. «Generate image» בממשק לא אמור לבזבז תור מתכנן בתקווה שהמודל יסכים.

אחרי תור Auto, **מתייגים את הודעת העוזר** בכלי שרץ (`image`, `graph`, …) כדי שה־UI יוכל לעטוף Mermaid,
להציג תמונה ולסמן את הבועה. **לא** משנים את הבוחר הדביק. המשתמש לא בחר כלי; המודל בחר, לתור הזה בלבד.

ניסיון חוזר של אותה הודעה יכול למחזר את התג (לכפות את אותו מומחה) או להריץ שוב Auto. כפייה פשוטה יותר
ותואמת «נסה שוב את התמונה הזו».

## 6. צורת הרגיסטרי

ההצהרות הן מה ש־Gemini רואה. המטא־דאטה הוא מה שהשרת שלכם רואה. שומרים את שניהם ברשימה אחת.

```ts
type HandoffTool = {
  name: string;           // חייב להתאים ל־FunctionDeclaration.name
  kind: "handoff";
  toolId: "image" | "graph"; // מזהה האפליקציה, לשימוש ב־UI וב־SSE
  argumentKey: "prompt" | "request";
  declaration: FunctionDeclaration;
};
```

איכות ההצהרה חשובה יותר מקוד ניתוב מבריק. ה־`description` הוא איך המודל מחליט. כותבים **מתי להשתמש**
ו**מתי לא**.

```ts
{
  name: "generate_image",
  description:
    "Generate or edit an image from a text description. Use when the user asks to draw, generate, create, imagine, or modify a picture.",
  parameters: {
    type: "object",
    properties: {
      prompt: {
        type: "string",
        description:
          "Full image prompt, including any requested edits to a previous image in the conversation.",
      },
    },
    required: ["prompt"],
  },
}
```

```ts
{
  name: "generate_graph",
  description:
    "Create a Mermaid diagram such as a flowchart, sequence diagram, architecture map, or ER chart. Use when the user asks for a graph, diagram, flowchart, or visual structure.",
  parameters: {
    type: "object",
    properties: {
      request: {
        type: "string",
        description: "What the diagram should show.",
      },
    },
    required: ["request"],
  },
}
```

החיפוש הוא `registry.find(t => t.name === functionCall.name)`. שמות לא מוכרים: מתעלמים ומסיימים עם
הטקסט שהמתכנן כבר שידר. לא מפילים את התור.

תיאורי הכלים ל־Gemini נשארים באנגלית: זה מה שהמודל אומן עליו.

## 7. גוף הבקשה (מתכנן)

כש**אין** כלי כפוי:

```json
{
  "contents": [ /* השיחה */ ],
  "systemInstruction": { "role": "system", "parts": [{ "text": "…" }] },
  "tools": [{ "functionDeclarations": [ /* מהרגיסטרי */ ] }],
  "toolConfig": {
    "functionCallingConfig": { "mode": "AUTO" }
  },
  "generationConfig": { "temperature": 1, "maxOutputTokens": 8192 }
}
```

כשכלי **כן** כפוי, משמיטים `tools` ו־`toolConfig`. במקום זאת מגדירים קונפיגורציה של מומחה בלבד (מודליות
תמונה, הוראת מערכת לדיאגרמה, …).

סיכום `mode`:

| Mode | שימוש |
| --- | --- |
| `AUTO` | צ׳אט ברירת מחדל. המודל רשאי לענות או לקרוא לפונקציה |
| `ANY` | חייב לקרוא לפונקציה (`allowed_function_names` אופציונלי) |
| `NONE` | אוסר קריאות לפונקציה |

XOR כפוי נקי יותר כ־«לדלג על כלים, ללכת למומחה» מאשר כ־`ANY`, כי יצירת תמונה היא **מודל אחר**. `ANY` על
מודל הצ׳אט לא יכול לפלוט בתים של PNG.

## 8. בקשת HTTP אחת מהמשתמש, שתי קפיצות מודל

משאירים את ה־API בדפדפן טיפש: `POST /chat/stream` פעם אחת. **השרת** מחזיק את הלולאה.

1. פותחים SSE. שולחים `meta` (ספק, מודל, אזור, בקשה מנוקה).
2. משדרים את המתכנן. מעבירים דלתאות **טקסט** גלויות. מתעלמים מחלקי `thought`. צוברים חלקי `functionCall`
   (`name` + `args`; ממזגים ארגומנטים הדרגתיים).
3. אם המתכנן נגמר **בלי** קריאת פונקציה → `done`.
4. אם הוא נגמר ב־handoff מוכר:
   - פולטים `event: tool` עם `{ id, name, args, model, region? }`
   - בונים בקשת מומחה (ראו §9)
   - משדרים את הקפיצה הזו על **אותו** SSE (`delta`, `image`, …)
   - ואז `done`
5. לא אוספים קריאות פונקציה בקפיצת המומחה. לא רקורסיה.

הלקוח:

- `onTool` → מגדיר `message.tool` (ואפשר לעדכן את המודל המוצג למומחה)
- משאיר את סמן הסטרימינג עד `done`
- מציג תמונות / Mermaid מאותה בועה

בועת המשתמש עדיין מציגה את הנוסח המקורי. רק **תור המשתמש האחרון כלפי הספק** משתמש ב־`prompt` / `request`
המשוכתבים מ־`args`. כך «תייצר לי תמונה של קוף» הופך לפרומפט תמונה תקין בלי לשקר בתמליל.

## 9. בניית בקשת המומחה

מעתיקים ספק, טמפרטורה, היסטוריה. ואז מתמחים.

**תמונה**

- מודל: Gemini התמונה שלכם (למשל `gemini-3.1-flash-image`)
- Vertex: מודלי תמונה לעיתים קרובות **גלובליים בלבד** — כופים את האזור הזה גם אם בהגדרות כתוב `europe-west1`
- `generationConfig.responseModalities = ["TEXT", "IMAGE"]`
- משמיטים thinking / `thinkingConfig` (מודלי תמונה דוחים אותו)
- מחזירים תמונות שנוצרו קודם להיסטוריה כ־`inlineData` כדי ש־«תכהה את זה» יוכל לערוך
- טקסט המשתמש האחרון = `args.prompt` אם קיים

**דיאגרמה**

- אותו מודל צ׳אט / אזור / thinking כמו המתכנן
- מוסיפים הוראת מערכת נסתרת: בלוק ` ```mermaid ` מגודר אחד, כותרת קצרה, בלי HTML
- טקסט המשתמש האחרון = `args.request` אם קיים
- UI: מציגים Mermaid מגודר כשההודעה הושלמה; אם התור מתויג `graph` ואין גדר, מתייחסים לכל התשובה כ־Mermaid
  ונופלים למסגרת קוד אם הניתוח נכשל

**שניהם**

- לא שולחים את `tools` של המתכנן בבקשת המומחה
- לא שולחים `cachedContent` של Vertex (ראו §11)

## 10. שידור חלקי `functionCall`

מקטעי המתכנן נראים כך:

```json
{
  "candidates": [{
    "content": {
      "parts": [{
        "functionCall": {
          "name": "generate_image",
          "args": { "prompt": "a monkey sitting on a red stool" }
        }
      }]
    },
    "finishReason": "STOP"
  }]
}
```

פרטים שנושכים:

- ארגומנטים עשויים להגיע **בהדרגה**. ממזגים אובייקטים עם אותו `name`; לוקחים את הצילום השלם האחרון אם השם
  משתנה.
- המתכנן עשוי לשדר פתיח טקסט קצר («אני אייצר את זה») **וגם** קריאת פונקציה. מעבירים את הטקסט, ואז עושים
  handoff. לא משמיטים אותו, ולא מתייחסים אליו כתשובה הסופית.
- מסננים חלקי `thought: true` מהסטרים הגלוי, כמו בצ׳אט רגיל.
- בתים של תמונה מגיעים כ־`inlineData` (`mimeType` + base64). פולטים אירוע SSE ייעודי `image`. שומרים blobs
  ב־IndexedDB / אחסון אובייקטים; **לעולם לא** משמרים base64 מלא ב־JSON של השיחה ב־`localStorage`. מצניעים
  בתים של תמונה בעקבות דיבאג.

אירועי SSE מומלצים:

| אירוע | מתי |
| --- | --- |
| `meta` | הסטרים נפתח (צילום בקשת המתכנן) |
| `delta` | טקסט גלוי מכל אחת מהקפיצות |
| `tool` | הוחלט handoff (`id`, `name`, `args`, `model` של המומחה) |
| `image` | המומחה ייצר נתוני תמונה inline |
| `done` / `error` | סופי |

## 11. מטמונים, thinking, ומוקשים אחרים

**מטמון הקשר מפורש ב־Vertex.** מטמון אינו ניתן לשינוי ונוצר עם סט כלים מסוים (או בלי). שליחת
`functionDeclarations` ליד `cachedContent` שלא נבנה עם הכלים האלה נכשלת. handoff של דיאגרמה גם מוסיף הוראת
מערכת שהמטמון לא מכיל. קפיצת תמונה משתמשת ב־**מודל אחר**. כלל מעשי: **מדלגים על `cachedContent` בתורי מתכנן
Auto ובכל קפיצת מומחה.** מטמון קידומת משתמע מצד הספק עדיין חל.

**Thinking.** משאירים אותו על המתכנן (הוא עוזר בבחירת כלי). מורידים אותו ממומחה התמונה.

**לא שמים את מודל התמונה בתפריט המודלים הרגיל.** זה לא מודל צ׳אט כללי. מנתבים אליו רק דרך כלי התמונה.

**לא שולחים חלקי טקסט ריקים.** אם תור בהיסטוריה הוא תמונה בלבד, שולחים `inlineData` בלי `{ text: "" }` ריק,
אלא אם ה־API דורש לפחות חלק אחד.

**בחירת כלי אינה מתאם מילות מפתח.** «תסביר איך עובדת יצירת תמונות» **לא** אמור לקרוא ל־`generate_image`.
תיאורים טובים + `AUTO` מטפלים בזה טוב יותר מביטוי רגולרי.

## 12. הוספת הכלי הבא

רשימת בדיקה:

1. מוסיפים רשומת רגיסטרי (`name`, `kind`, `declaration`, איך בונים את המטען של המומחה או ה־loop).
2. אם **handoff**: מממשים את הקפיצה השנייה (מודל, קונפיג, שכתוב היסטוריה). מתייגים `message.tool`.
3. אם **loop**: מריצים, מוסיפים `functionResponse`, קוראים שוב למודל הצ׳אט עם אותן הצהרות; מגבילים מספר
   סבבים.
4. אם **מובנה** (Search): מוסיפים את אובייקט הכלי המובנה של Gemini; עדיין `AUTO`.
5. בדיקות: גוף Auto כולל את השם החדש; XOR כפוי עדיין משמיט `tools`; `functionCall` מזויף של מתכנן מפעיל את
   ה־fetch השני.

לא אמור להיות צורך ב־`if (tool === "image")` חדש בראש פרוקסי הסטרים. מחפשים ברגיסטרי, ואז עוברים לפי
`kind`.

## 13. בדיקות שכדאי לכתוב קודם

אלה תופסות את התכנון, לא רק את צנרת ה־HTTP.

1. **גוף Auto** כולל `functionDeclarations` ו־`AUTO`. בלי `responseModalities`.
2. **תמונה כפויה** בלי `tools` / `toolConfig`, **עם** `responseModalities`.
3. SSE של מתכנן עם `functionCall.name = "generate_image"` גורם ל־fetch **שני** למודל התמונה, פולט
   `event: tool` ואז `event: image`, וחלק המשתמש האחרון אצל המומחה הוא `args.prompt`.
4. אותו דבר ל־`generate_graph`: ה־fetch השני נשאר על מודל ה־**צ׳אט**, הוראת מערכת Mermaid קיימת, בלי כלי
   מתכנן בקפיצה הזו.
5. `functionCall` בשם לא מוכר לא זורק; הסטרים עדיין מסיים ב־`done`.

---

## 14. מודל מנטלי מינימלי

- **Auto** = מודל צ׳אט + הצהרות + `AUTO`.
- **Force** = מדלגים על המתכנן, מריצים את המומחה.
- **Handoff** = קריאת מודל שנייה, אותו SSE, המשתמש רואה את פלט המומחה.
- **Loop** = `functionResponse` חזרה למודל הצ׳אט (בהמשך).
- **נתב Lite** = קפיצה נוספת בכל הודעה; מדלגים עד שיש סיבת עלות.

זה כל המוצר: כפתור שליחה אחד, מודל שכבר יודע לבחור פונקציה, ורגיסטרי שאפשר להגדיל.
