# מעבדת Context Cache של Vertex AI — מדריך בעברית

> המדריך נבדק מול התיעוד הרשמי של Google Cloud בתאריך 14.08.2026. תמיכת מודלים, מגבלות ותמחור עשויים להשתנות; לפני שימוש בייצור יש לבדוק את המקורות הרשמיים המקושרים בסוף.

## מה לומדים במעבדה

מטמון הקשר מאפשר לבקשות חוזרות להפנות לקלט גדול שנשמר מראש, במקום לשלוח אותו מחדש בכל בקשה. המנגנון מתאים למסמך, וידאו, אודיו, הוראות מערכת או הגדרות כלים שמשותפים לפרומפטים רבים.

המעבדה מדגימה מחזור חיים מלא של **מטמון מפורש (explicit cache)**:

1. יצירת משאב `CachedContent`.
2. בדיקת המטא־דאטה ומספר הטוקנים שהשירות מדווח.
3. שימוש בשם המשאב בבקשת יצירה.
4. הוכחת הפגיעה במטמון באמצעות `usageMetadata.cachedContentTokenCount`.
5. הארכה או החלפה של זמן הפקיעה.
6. מחיקה מיד בסיום הניסוי.

העמוד מבצע קריאות אמיתיות ל־Vertex AI. אחסון של מטמון מפורש ממשיך להיות כרוך בחיוב עד למחיקה או לפקיעה.

## מטמון מפורש לעומת מטמון משתמע

| סוג | כיצד הוא פועל | מה האפליקציה מנהלת |
| --- | --- | --- |
| מפורש | האפליקציה יוצרת משאב `CachedContent` בעל שם ומעבירה את שמו בבקשות הבאות. | תוכן, מודל, פקיעה, שימוש חוזר ומחיקה. |
| משתמע | Vertex עשוי להשתמש אוטומטית בקידומות קלט זהות במודלים נתמכים. | סידור התוכן הגדול והיציב בתחילת הבקשה ובדיקת נתוני השימוש; אין משאב לניהול. |

מטמון מפורש מתאים כשדרושים מחזור חיים צפוי ושימוש חוזר מכוון באותו הקשר גדול. מטמון משתמע מתאים כשהתנהגות best-effort מספיקה ואין רצון לנהל משאבי מטמון.

## רלוונטיות לסדרת Gemini 3

בורר המודלים מבוסס על טבלת התמיכה הרשמית במטמון מפורש. במועד בדיקת המדריך הרשימה כוללת:

- `gemini-3.6-flash`
- `gemini-3.5-flash-lite`
- `gemini-3.5-flash`
- `gemini-3.1-pro-preview`
- `gemini-3.1-flash-lite`
- `gemini-3-flash-preview`

לפי התיעוד, קלט מינימלי למטמון מפורש ב־Gemini 3 הוא **4,096 טוקנים**. דוגמת הלימוד שהעמוד מייצר ארוכה מהסף בכוונה, אך המונה בדפדפן הוא הערכה המבוססת על מספר תווים בלבד. הערך המוסמך הוא `usageMetadata.totalTokenCount` שחוזר מ־Vertex בזמן היצירה.

לחלק ממודלי התצוגה המקדימה יש ספים אחרים למטמון משתמע. אין להסיק מסף המטמון המפורש על ההתנהגות המשתמעת.

## דרישות מוקדמות

1. הפעלת Vertex AI API בפרויקט Google Cloud הנבחר.
2. התחברות מקומית באמצעות Application Default Credentials:

   ```powershell
   gcloud auth application-default login
   ```

3. הגדרת `GCP_PROJECT` בקובץ `.env`, או הזנת פרויקט בעמוד.
4. מתן הרשאות Vertex AI המתאימות לזהות. משאב ה־REST מתעד הרשאות כגון `aiplatform.cachedContents.create`, `get`, `list`, `update`, `delete`, וכן הרשאת החיזוי הנדרשת ליצירה.
5. עבור מקור `gs://`, יש לוודא שלזהות יש הרשאת קריאה ושסוג הקובץ נתמך במודל.

השרת משיג את אסימון OAuth. פרטי הזדהות ואסימוני גישה לעולם אינם חוזרים לדפדפן.

## מבנה המשאב ונקודות הקצה

שם האוסף:

```text
projects/{project}/locations/{location}/cachedContents
```

כתובת אזורית:

```text
https://{location}-aiplatform.googleapis.com/v1/projects/{project}/locations/{location}/cachedContents
```

כתובת גלובלית:

```text
https://aiplatform.googleapis.com/v1/projects/{project}/locations/global/cachedContents
```

בשימוש במטמון, בקשת `:generateContent` של המודל מכילה את שם המשאב שהוחזר בשדה `cachedContent`.

## שדות בקשת היצירה

תצוגת ה־JSON בעמוד מציגה את המבנה לפני שנשלחת בקשה.

| שדה | משמעות | ניתן לשינוי? |
| --- | --- | --- |
| `model` | שם משאב מלא של מודל המפרסם. | לא |
| `displayName` | תווית אנושית שמקלה על איתור. | לא |
| `systemInstruction` | הוראה משותפת לכל שימוש במטמון. | לא |
| `contents` | ההקשר השמור, כרשימת חלקים (parts): אפשר לשלב `text`, `inlineData` ו־`fileData` באותה בקשה. | לא |
| `tools` / `toolConfig` | הגדרות כלים חוזרות. ה־API תומך בהן, אך גרסת המעבדה הראשונה אינה כוללת עורך עבורן. | לא |
| `ttl` | משך זמן מרגע עיבוד הבקשה, לדוגמה `3600s`. | כן |
| `expireTime` | זמן פקיעה מוחלט בפורמט RFC 3339. | כן |
| `encryptionSpec.kmsKeyName` | מפתח הצפנה בניהול הלקוח (CMEK), אופציונלי. | לא |

`ttl` ו־`expireTime` הם union: שולחים אחד מהם בלבד. אם לא נשלח זמן פקיעה, ברירת המחדל המתועדת היא 60 דקות. המינימום הוא דקה אחת, ולא מתועד ערך מקסימלי.

דוגמה עם טקסט מוטמע:

```json
{
  "model": "projects/PROJECT/locations/global/publishers/google/models/gemini-3.6-flash",
  "displayName": "policy-learning-cache",
  "systemInstruction": {
    "parts": [{ "text": "ענה רק לפי המדיניות שבמטמון." }]
  },
  "contents": [{
    "role": "user",
    "parts": [{ "text": "מסמך משותף ארוך מספיק…" }]
  }],
  "ttl": "3600s"
}
```

דוגמה לשילוב טקסט וקבצים. `parts` היא רשימה מסודרת, ולכן מטמון אחד יכול להכיל מסמך לימוד, קובץ PDF שהועלה ואובייקט ב־Cloud Storage בו־זמנית:

```json
{
  "model": "projects/PROJECT/locations/us-central1/publishers/google/models/gemini-3.6-flash",
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "מסמך משותף ארוך מספיק…" },
      {
        "inlineData": {
          "mimeType": "application/pdf",
          "data": "JVBERi0xLjcK…"
        }
      },
      {
        "fileData": {
          "fileUri": "gs://BUCKET/manual.pdf",
          "mimeType": "application/pdf"
        }
      }
    ]
  }],
  "expireTime": "2026-08-14T15:30:00Z"
}
```

`inlineData` נושא את בייטי הקובץ עצמם כ־base64 בתוך הבקשה, ואילו `fileData` נושא רק מצביע לאובייקט שכבר קיים ב־Cloud Storage. שניהם הופכים לטוקנים שמורים, ולכן שניהם נספרים לצורך מינימום 4,096 הטוקנים.

## מגבלות גודל ואחסון

- מטמון מפורש של Gemini 3 דורש כיום לפחות 4,096 טוקני קלט.
- תוכן מוטמע מסוג blob או text מוגבל ל־10 MB.
- קידוד base64 מנפח את הקובץ בכשליש, והכול חייב להיכנס לבקשה אחת; המעבדה מגבילה ל־15 MB לכל קריאת יצירה.
- לתוכן גדול יותר יש להשתמש ב־Cloud Storage.
- פורמטים ומגבלות מדיה תלויים גם במודל הנבחר.
- המטמון שייך לפרויקט ולמיקום יחידים, ויש להשתמש בו מול נקודת קצה תואמת באותו מיקום.

## שימוש במטמון והוכחת פגיעה

בקשת יצירה מפנה לשם המטמון:

```json
{
  "cachedContent": "projects/PROJECT/locations/global/cachedContents/CACHE_ID",
  "contents": [{
    "role": "user",
    "parts": [{ "text": "באיזו תדירות יש לבדוק עלויות?" }]
  }]
}
```

העמוד מדגיש את השדה:

```text
usageMetadata.cachedContentTokenCount
```

ערך חיובי הוא הראיה של הספק לכך שנעשה שימוש בקלט מהמטמון. זמן תגובה קצר אינו הוכחה: רשת, קיבולת, אורך הפלט ותשתית חמה משפיעים גם הם על המדידה.

כדאי להשוות גם את `promptTokenCount`, את `candidatesTokenCount` ואת `totalTokenCount`.

יש לשים לב גם ל־`thoughtsTokenCount`: טוקני החשיבה של Gemini 3 נגרעים מ־`maxOutputTokens`, אך אינם נכללים ב־`candidatesTokenCount`. לכן תשובה יכולה להיעצר עם `MAX_TOKENS` אחרי מעט מאוד טוקנים גלויים. יש לחבר את שני המספרים לפני שמסיקים שהתקציב מספיק, או להנמיך את `thinkingLevel`.

## שימוש במטמון מתוך הצ׳אט

במסך **הגדרות → מטמון הקשר** אפשר להפעיל את היכולת עבור שיחות רגילות. כאשר שיחה כוללת קבצים, האפליקציה מחשבת טביעת אצבע של החומר (מודל, מיקום, הוראת מערכת וכל הקבצים) ואז:

1. משתמשת מחדש במטמון חי בעל אותה טביעת אצבע, או
2. יוצרת מטמון חדש ושומרת את שם המשאב ואת `expireTime` ברישום המקומי של הדפדפן.

מכאן והלאה הבקשות שולחות רק את `cachedContent` ואת התור החדש. הקבצים והוראת המערכת מושמטים מגוף הבקשה במכוון, מפני שהמטמון כבר מכיל אותם ו־Vertex דוחה הוראת מערכת כפולה.

מכיוון שתוכן שמור אינו ניתן לשינוי, כל דבר שמשנה את טביעת האצבע — החלפת מודל, שינוי הוראת המערכת או הוספת קובץ — יוצר מטמון **חדש**. הישן ממשיך להיות מחויב עד תום ה־TTL שלו, ולכן רשימת ההגדרות מציגה כל מטמון חי עם ספירה לאחור וכפתור מחיקה. רשומות נעלמות מהרשימה עם הפקיעה, מכיוון ש־Vertex כבר הפסיק להגיש ולחייב עליהן.

שלב היצירה במעבדה והצ׳אט חולקים הגדרת `thinkingLevel` אחת, שנשלחת כ־`generationConfig.thinkingConfig.thinkingLevel`.

## עדכון זמן הפקיעה

רק זמן הפקיעה ניתן לעדכון. המעבדה שולחת `PATCH` עם מסכת עדכון:

```text
?updateMask=ttl
```

וגוף לדוגמה:

```json
{ "ttl": "7200s" }
```

לזמן מוחלט משתמשים ב־`updateMask=expireTime`. עדכון TTL נמדד מזמן העדכון, ולא מזמן היצירה המקורי.

כדי לשנות מודל, תוכן, הוראת מערכת, שם תצוגה, כלים או מפתח הצפנה, צריך ליצור מטמון חדש.

## חיוב וניקוי

מטמון מפורש עשוי לכלול חיוב עבור עיבוד הקלט ביצירה, אחסון הטוקנים לאורך זמן, קלט מטמון ופלט בזמן שימוש. יש לבדוק תמחור עדכני למודל ולאזור המדויקים.

מחיקה מוקדמת מפסיקה זמן אחסון עתידי. העמוד דורש לחיצה שנייה לפני מחיקה משום שהיא בלתי הפיכה. אי אפשר להחיות מטמון שנמחק או פג; יש ליצור חדש.

הבדיקות האוטומטיות במאגר מדמות תשובות של Google ואינן יוצרות משאבי ענן או צורכות מכסה.

## CMEK ואבטחה

- את `encryptionSpec.kmsKeyName` יש להעביר בזמן היצירה.
- לפי התיעוד הנוכחי, CMEK אינו זמין דרך נקודת הקצה `global`; יש לבחור אזור נתמך ומיקום מפתח תואם.
- התוכן צריך להישאר בגבולות הפרויקט, ה־IAM, מדיניות הארגון ומדיניות הנתונים המתאימים.
- אין להזין סודות בטופס רק משום שהאפליקציה מקומית. מצב הטופס וכלי הפיתוח של הדפדפן אינם כספת סודות.

## פתרון תקלות

| תסמין | מה לבדוק |
| --- | --- |
| שגיאת מינימום טוקנים | יצירת דוגמה גדולה יותר; יש לסמוך על ספירת Vertex ולא על ההערכה בדפדפן. |
| מודל לא נמצא או לא נתמך | טבלת התמיכה העדכנית והמיקום הנבחר. מזהי preview עשויים להשתנות. |
| הרשאה נדחתה | זהות ADC, פרויקט, IAM, מדיניות ארגון ו־VPC Service Controls. |
| אין `cachedContentTokenCount` | גוף הבקשה מפנה לשם המדויק והמודל תומך במטמון. |
| המטמון פג | יצירת מטמון חדש. אי אפשר להאריך משאב לאחר פקיעתו. |
| CMEK נדחה ב־`global` | בחירת אזור נתמך ומיקום מפתח תואם. |
| מקור GCS נדחה | URI, הרשאת אובייקט, MIME, תמיכת המדיה של המודל וגודל הקובץ. |
| הרשימה ריקה | הרשימה מוגבלת לפרויקט ולמיקום שנבחרו. |

## ניסויים מומלצים

1. צור מטמון לשעה מדוגמת הלימוד ורשום את `totalTokenCount`.
2. שאל שתי שאלות שונות והשווה את `cachedContentTokenCount` ואת זמן התגובה.
3. הארך את ה־TTL, רענן מטא־דאטה וצפה בשעון משתנה.
4. הצג את רשימת המשאבים במיקום ובחר שוב באותו מטמון.
5. מחק אותו מיד בסיום.
6. בנפרד, בדוק מטמון קידומת משתמע והשווה את נתוני השימוש בלי לערבב בין המנגנונים.
