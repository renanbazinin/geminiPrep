# בדיקת אזורים של Vertex AI — מדריך בעברית

## מטרת הבדיקה

בדיקת האזורים עונה באמצעות ראיות על שאלה ממוקדת: **האם מודל publisher מסוים של Vertex AI מגיב ממיקום מסוים?**

הבדיקה שולחת בקשת `generateContent` מינימלית לכל צמד נבחר של מודל × אזור ומסווגת את תוצאת ה־HTTP. היא אינה מודדת איכות מודל, תפוקה או תושבות נתונים.

## דרישות מוקדמות

1. בחירת פרויקט Google Cloud שבו Vertex AI API מופעל.
2. התחברות מקומית עם Application Default Credentials:

   ```powershell
   gcloud auth application-default login
   ```

3. הגדרת `GCP_PROJECT` בקובץ `.env`. ממשק הבדיקה מאפשר פרויקט זמני רק אם לא הוגדר פרויקט בשרת.
4. מתן הרשאה לזהות המחוברת להפעיל publisher models בפרויקט.

הבדיקה משתמשת ב־OAuth/ADC. המשתנה `GEMINI_API_KEY` אינו קשור אליה.

## מבנה נקודות הקצה

```text
/v1/projects/{project}/locations/{region}/publishers/google/models/{model}:generateContent
```

| סוג מיקום | דוגמה ל־hostname |
| --- | --- |
| גלובלי | `aiplatform.googleapis.com` |
| multi-region אירופה | `aiplatform.eu.rep.googleapis.com` |
| multi-region ארה״ב | `aiplatform.us.rep.googleapis.com` |
| אזור יחיד | `{region}-aiplatform.googleapis.com` |

כל קריאה שולחת `ping` עם טמפרטורה `0` ועד 16 טוקני פלט. מודלי Flash Image גם מגדירים `responseModalities: ["TEXT", "IMAGE"]` ומכסת טוקנים גבוהה יותר, כי בקשת טקסט בלבד תיכשל גם באזור שמגיש את המודל.

## פסקי דין

| תוצאה | משמעות |
| --- | --- |
| זמין | נקודת הקצה החזירה HTTP 2xx. |
| מגבלת מכסה | HTTP 429; המודל מפורסם במיקום, אך המכסה מנעה יצירה. נספר כזמין. |
| לא מוגש | HTTP 404, או הודעת HTTP 400 מתאימה שמציינת שהמודל אינו זמין במיקום. |
| הרשאה נדחתה | HTTP 401 או 403. התוצאה אינה מוכיחה שהמודל לא זמין. |
| פג זמן | הבקשה חרגה מזמן ההמתנה. timeout אינו נחשב לחוסר זמינות. |
| שגיאה | כשל תעבורה או שגיאת ספק שלא סווגה. כשלי תעבורה מקבלים ניסיון נוסף אחד. |

לחיצה על תא במטריצה מציגה את נקודת הקצה, הסטטוס, זמן התגובה, מידע על ניסיון חוזר והודעת הספק. הכפתור **העתקת Markdown** מעתיק מטריצה קומפקטית להערות הלימוד.

## הגדרה דרך הסביבה

אפשר להרחיב את הקטלוג באמצעות משתני סביבה מופרדים בפסיקים:

- `VERTEX_PROBE_MODELS`
- `VERTEX_PROBE_REGIONS`
- `VERTEX_PROBE_DEFAULT_REGIONS`
- `VERTEX_PROBE_TIMEOUT_MS` — ברירת מחדל `30000`
- `VERTEX_PROBE_CONCURRENCY` — ברירת מחדל `8`

מזהים לא מוכרים נשמרים, ולכן אפשר לבדוק מודל או מיקום חדשים בלי לשנות קוד.

## מגבלות ופרשנות

- התוצאה היא תצפית נקודתית עבור פרויקט וזהות מסוימים.
- קטלוגי מודלים ומיקומי הגשה משתנים עם הזמן.
- IAM, מדיניות ארגון, VPC Service Controls, קיבולת ומכסה עשויים להשפיע.
- המטריצה מפעילה קריאות יצירה אמיתיות ועשויה לצרוך מכסה.
- זמן התגובה מיועד לאבחון ואינו benchmark מבוקר.
- Gemini Developer API משתמש בנקודת קצה גלובלית ונמצא מחוץ לבדיקה הזו.

## מסקנת הלימוד

חשוב להפריד בין שלושה מצבים: מודל מפורסם וניתן להפעלה; מודל מפורסם אך חסום כרגע בגלל מכסה או הרשאה; ומודל שאינו מפורסם במיקום. תוצאת pass/fail יחידה מסתירה אם מקור הבעיה הוא טופולוגיה, הרשאות או קיבולת.
